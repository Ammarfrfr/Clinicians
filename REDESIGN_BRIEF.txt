QALAM - MEDICAL SCRIBE APP REDESIGN BRIEF
==========================================

CURRENT STATE:
- Product: Qalam (Medical Scribe App for Indian doctors)
- Purpose: Transcribe doctor-patient conversations in Hinglish/Gujarati → Generate clinical notes in English
- Users: Busy doctors in India who need to save time on documentation
- Tech: React + Vite frontend, Express backend, MongoDB, Groq Whisper, AssemblyAI
- Current Issue: UI/UX needs professional redesign for production use

TARGET AUDIENCE:
- Busy doctors in hospitals/clinics (India)
- Age 35-65, tech-aware but not designers
- Value: Time savings (4 hours/day → 30 mins documentation)
- Problem they face: Documentation takes too much time, causes patient backlogs

CURRENT FEATURES TO PRESERVE:
1. Audio recording (one-click record patient consultation)
2. Hinglish/Gujarati transcription (auto-translate to English)
3. AI-generated clinical notes from conversation
4. Patient management (add/edit/delete patients)
5. Past visit history & note editing
6. Vital signs entry (BP, HR, SpO2, temp, weight)
7. Note export as PDF
8. Dark/light mode toggle
9. Processing status indicators

REDESIGN REQUIREMENTS:

VISUAL DESIGN:
- Professional, clean, medical aesthetic (not gaming-like)
- Color scheme: Blues/greens (medical trust colors) instead of current dark mode
- Typography: Clear, readable (doctors over 40+ have aging eyes)
- Icons: Medical symbols, intuitive workflow
- Whitespace: More breathing room, less cramped
- Mobile-first (doctors use phones/tablets in clinics)
- Accessibility: WCAG AA standard (size 14+ font minimum)

LAYOUT IMPROVEMENTS:
- Reduce sidebar clutter (too many options at once)
- Cleaner patient list (sortable, searchable, filterable)
- Recording button: Larger, more prominent, one clear action
- Transcript display: Two-column (Doctor | Patient) with different colors
- Note editor: Distraction-free, clean interface
- Vitals form: Quick entry (not scattered across screen)
- Past visits: Better timeline view, easy to scan

UX IMPROVEMENTS:
- Onboarding flow for first-time users
- Loading states with skeleton screens
- Better error messages (currently says "Network Error")
- Confirmation dialogs before delete
- Undo for accidental actions
- Keyboard shortcuts for power users
- Export progress indicator
- Form validation with helpful errors

CONTENT/COPY:
- Replace technical jargon with doctor-friendly terms
- Button labels: Clear actions ("Save & Continue", not "Submit")
- Empty states: Helpful prompts when no patients exist
- Success messages: Confirm what just happened
- Help text: Brief explanations for each section
